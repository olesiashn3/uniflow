# Стратегія тестування UniFlow (pytest + coverage)

## Інструменти
- **pytest** — збір і запуск тестів, фікстури, параметризація.
- **pytest-cov** — покриття рядків/гілок; звіти **HTML** та **XML** (для CI, SonarQube тощо).

## Розташування
- Каталог **`tests/`** — усі автоматичні тести.
- **`tests/conftest.py`** — спільні фікстури (`app`, `client`, `db`, користувач, in-memory репозиторій, скидання singleton Observer).
- **`tests/helpers.py`** — `make_event_stub`, тестові дублікати користувачів для in-memory стрічок.
- База для інтеграційних тестів моделей: **`sqlite:///:memory:`** через змінну середовища `DATABASE_URL` (встановлюється на початку `conftest.py` до імпорту застосунку).

## Практики
1. **Параметризація** (`@pytest.mark.parametrize`) — для комбінацій фільтрів, сортувань, довжин рядків, форматів email; уникати копіпасти сотень окремих функцій.
2. **In-memory репозиторій** — швидкі тести без MySQL для правил фільтрації та пагінації.
3. **Ізоляція Observer** — скидання модульного `_subject` у фікстурі, щоб тести не залежали від порядку запуску.
4. **Маркери** — за потреби додавай `@pytest.mark.slow` для тестів з великими даними; у `pytest.ini` зареєструй маркери в `markers`.

## Команди (локально)

З кореня репозиторію після `pip install -r requirements.txt`:

```text
pytest
```

З покриттям (термінал + HTML + XML у `htmlcov/` та `coverage.xml`):

```text
pytest --cov=app --cov-report=term-missing --cov-report=html:htmlcov --cov-report=xml:coverage.xml
```

Перегляд HTML-звіту: відкрити файл `htmlcov/index.html` у браузері.

## Політика для ШІ (TDD)
- Нова поведінка: **тест(и) → код → рефакторинг**.
- Не знижувати поріг якості тестів без узгодженого причинного запису (наприклад, видалення мертвого коду).
